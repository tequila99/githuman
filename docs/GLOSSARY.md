# Глоссарий

Один термин — одно понятие. Используйте слово из колонки «Термин» в коде, комментариях, именах и
сообщениях интерфейса. Слова из колонки «Не писать» означают другое или двусмысленны.

Правило комментариев (ASD-STE100) — в [CLAUDE.md](../CLAUDE.md), раздел «Стиль кода». Новое понятие
сначала добавляется сюда, потом используется в коде.

## Git и изменения

| Термин | По-русски | Значение | Не писать |
|---|---|---|---|
| `repository` | репозиторий | Git-репозиторий, в котором запущено приложение. Сервер работает с одним. | `repo` в текстах (в коротких именах допустимо) |
| `worktree` | рабочее дерево | Файлы на диске. В коде — ref `WORKTREE`. | `working tree`, `disk copy` |
| `index` | индекс | Состояние git-индекса, то есть staged-содержимое. В коде — ref `INDEX`. | `staging area`, `cache` |
| `staged` / `unstaged` | в индексе / не в индексе | Изменения, добавленные в индекс, и остальные. Вкладки `Staged` и `Unstaged`. | `cached`, `indexed`, `pending` |
| `diff` | diff | Различия между двумя состояниями файла или всех файлов. | `patch`, `changeset` |
| `diff file` | файл в diff | Один изменённый файл в diff (тип `DiffFile`): путь, статус, hunks. | `changed file` для объекта данных |
| `hunk` | hunk | Непрерывный блок изменённых строк в diff-файле. | `chunk`, `block` |
| `card` | карточка | Раскрываемый блок одного diff-файла в панели diff (`DiffFileCard`). | `panel`, `item` |
| `folder` | папка | Каталог в дереве файлов (браузер файлов и дерево Changes). В агентском контексте то же понятие называется `directory`. | `dir` в текстах |
| `compressed folder` | сжатая папка | Строка дерева Changes, которая объединяет цепочку папок с одной вложенной папкой (`src/web/components`), как на GitHub (#76). | `merged folder`, `chain` |
| `scroll window` | окно прокрутки | Видимая часть элемента прокрутки панели (`QScrollArea.getScrollTarget()`). | `view`, `viewport` в комментариях |
| `sticky header` | липкая шапка | Шапка карточки, которая остаётся у верхнего края окна прокрутки, пока её карточка видна (#77). | `pinned header`, `fixed header` |
| `full file` | весь файл | Режим карточки: показать файл с диска целиком, а не только hunks. | `full view` в текстах |
| `virtual list` | виртуальный список | Список, в котором монтируются только карточки или строки рядом с окном прокрутки. | `lazy list`, `windowed list` |
| `row segment` | сегмент строк | Часть строк hunk или файла, которая монтируется целиком (`RowSegment`). | `chunk`, `block`, `page` |
| `mount queue` | очередь монтажа | Очередь сегментов, которые вошли в зону монтажа и ждут кадра (`mount-queue.ts`, ADR 0040). | `scheduler`, `batch` |
| `row budget` | бюджет строк | Сколько строк очередь монтажа монтирует за один кадр. | `chunk size`, `limit` |
| `mount margin` | зона монтажа | Расстояние вокруг окна прокрутки, в котором сегмент монтируется (2000 px). | `buffer`, `prefetch area` |
| `preamble` | преамбула | Неизменённые строки файла перед hunk (до 60, начало выбирается по отступам; для Vue — ещё тег секции). Нужны подсветке как состояние грамматики, в интерфейсе не показываются (ADR 0036). | `context`, `header`, `prefix` |
| `slice` | кусок | Часть строк файла, которую токенизация обрабатывает за один шаг (ADR 0035). | `chunk`, `portion`, `batch` |
| `warm-up` | прогрев | Загрузка движка и грамматики и разбор образца до первого запроса подсветки. | `preload`, `prefetch` |
| `hold` | удержание | Карточка или просмотр файла показывает спиннер вместо кода, пока не пришёл первый кусок токенов. | `wait`, `block` |
| `summary` | сводка | Diff-файл без hunks: пути, статус, счётчики, подпись (`DiffFileSummary`, ADR 0033). | `stub`, `header` |
| `signature` | подпись | Строка сводки из обеих сторон diff. Равные подписи значат равные hunks (ADR 0034). | `hash`, `version` |
| `card state` | состояние карточки | Состояние карточки, которое переживает её размонтирование: режим, wrap, черновики (`card-state-store`). | `cache` |

## Ревью и комментарии

| Термин | По-русски | Значение | Не писать |
|---|---|---|---|
| `review` | ревью | Сохранённый снимок diff с комментариями и статусом (`in_progress`, `approved`, `changes_requested`). | `session`, `PR` |
| `active review` | активное ревью | Ревью текущей ветки, в которое добавляются комментарии. | `current review`, `open review` |
| `snapshot` | снимок | Diff, замороженный при создании ревью (ADR 0003). Не путать с `worktree`: снимок не меняется. | `copy`, `backup` |
| `comment` | комментарий | Заметка ревьюера к строке, диапазону строк или файлу ревью. | `note`, `remark` |
| `thread` | ветка комментариев | Комментарии к одному месту в diff, показанные вместе. Только для комментариев ревью. | `thread` в других смыслах (например, «передать по цепочке») |
| `resolved` | решён | Признак комментария: вопрос закрыт. Непроверенные комментарии — `unresolved`. | `closed`, `done` |
| `suggestion` | предложение правки | Текст замены, приложенный к комментарию. | `fix`, `patch` |
| `draft` | черновик | Неотправленный текст формы комментария. Очищается только после успешной отправки. | `pending text` |
| `anchor` | привязка | Место формы нового комментария: номера выделенных строк и их текст (`comment-anchor.ts`). | `selection` для сохранённого места |

## Агенты и чаты

| Термин | По-русски | Значение | Не писать |
|---|---|---|---|
| `agent` | агент | Внешняя программа, которая говорит по ACP (Claude Code, Cursor, Codex, pi). В интерфейсе — «Agent». | `harness`, `bot`, `assistant` |
| `preset` | пресет | Запись в конфиге о том, как запустить агента: команда, аргументы, пакет-адаптер (`AgentPreset`). | `agent config` |
| `adapter` | адаптер | Программа-мост между ACP и агентом, если у агента нет собственного ACP (например `claude-agent-acp`). | `wrapper`, `shim` |
| `session` | сессия | Серверный объект: процесс агента и его ACP-сессия (`AgentSession`, `/api/agent/sessions`). | `chat` для серверной части |
| `chat` | чат | То, что видит пользователь: вкладка и лента одной сессии. Каждая сессия — ровно один чат. | `conversation`, `dialog` |
| `transcript` | лента | Список записей чата: ваши сообщения, ответы, вызовы инструментов. | `history`, `log` (лог — другое) |
| `prompt` | запрос | Один ход пользователя: текст и контекст, отправленные агенту. | `query`, `request` для хода |
| `turn` | ход | Время от отправки запроса до ответа агента (`stop`). Статус сессии в ходе — `busy`. | `run`, `round` |
| `context` | контекст | Элементы, приложенные к запросу: `diff`, `file`, `directory`, `review`, `attachment`. | `payload`, `input` |
| `directory` | директория (в интерфейсе — папка, Folder) | Папка репозитория. В упоминании и поиске её путь заканчивается на `/`, в элементе контекста `directory` — без `/`. | `dir` в текстах, `folder` в коде агентского контекста |
| `resource URI` | URI ресурса | Идентификатор встроенного текста в запросе (`githuman://diff/…`, `…/review/…`, `…/attachment/…`). Не адрес, не разбирается. Подробности — [agent-context-uris.md](agent-context-uris.md). | `deeplink`, `link` |
| `voice input` | голосовой ввод | Распознавание речи в поле ввода чата по удержанию кнопки микрофона (Web Speech API браузера, #82). Текст попадает в поле один раз, при отпускании кнопки; отправка — отдельное действие. | `dictation`, `speech to text` в текстах |
| `recognition run` | сеанс распознавания | Один запуск распознавателя речи браузера от `start()` до события `end`. Chrome сам завершает долгий или тихий запуск; пока кнопка удерживается, новый запуск продолжает текст. | `session` (это агентская сессия) |
| `mention` | упоминание | Путь файла или директории репозитория, вставленный в поле ввода как `@путь` (директория — `@путь/`). Превращается в элемент контекста `file` или `directory`. | `reference`, `tag` |
| `attachment` | вложение | Файл или изображение, загруженное с компьютера пользователя. Не из репозитория. | `upload` (как существительное) |
| `tool call` | вызов инструмента | Действие агента (чтение, правка, команда). В событиях — `tool`. | `action`, `step` |
| `permission request` | запрос разрешения | Вопрос агента перед действием; пользователь выбирает вариант. | `confirmation`, `approval request` |
| `auto-approve` | автоподтверждение | Флаг сессии: сервер сам отвечает «разрешить» на запросы разрешений. Выключен по умолчанию. | `yolo`, `bypass`, `trust mode` |
| `stream` | поток | Единый SSE-поток `/api/agent/events` со всеми чатами страницы. | `channel`, `socket` |
| `send queue` | очередь отправки | Сообщения одного SSE-соединения, которые ждут записи в сокет (`safeSend`). Полная очередь (`MAX_QUEUED_MESSAGES`) или зависшая отправка (`STALL_TIMEOUT_MS`) закрывает соединение, клиент переподключается (#85). | `buffer` (занят буфером сессии), `backlog` |
| `envelope` | конверт | Событие потока вместе с `sessionId` и сквозным `id` (`AgentStreamEnvelope`). | `message`, `packet` |
| `session state` | состояние сессии | Текущие `status`, `autoApprove`, `config` и открытые запросы разрешений чата (`AgentSessionState`). Сервер шлёт его в потоке перед повтором событий. Не путать с `snapshot` ревью. | `snapshot` (занят), `summary` |
| `panel` | панель | Правая панель агента. В коде — `AgentSidebar`. | `drawer` в текстах для пользователя |

## Безопасность

| Термин | По-русски | Значение | Не писать |
|---|---|---|---|
| `loopback` | loopback | Адрес `127.0.0.1`/`::1`/`localhost`. | `local host` |
| `local request` | локальный запрос | Запрос с этой машины: loopback-сокет, loopback-`Host`, совпадающий `Origin`, только loopback в `X-Forwarded-For` (`isLocalRequest`, ADR 0079). Один `Host` локальным запрос не делает. | `localhost request`, `trusted request` |
| `device` | устройство | Браузер в сети с секретом в cookie; запись в таблице `devices`. Состояния: `pending` (ждёт подтверждения) и `trusted` (доверенное). | `client`, `session` |
| `pairing` | сопряжение | Запрос доступа устройства и его подтверждение в localhost-вкладке по совпадающему коду. | `login`, `auth` |
| `pairing code` | код сравнения | Шесть цифр на экране устройства. Оператор вводит их в localhost-вкладке; localhost-вкладка, список устройств и консоль кода не показывают (ADR 0080). | `PIN`, `password` |
| `allowed host` | допустимый хост | Значение `Host`, которое сервер принимает от запроса из сети: адреса интерфейсов машины и имена из `--allowed-host`. | `whitelist` |

## Известные исключения

Имена, которые не подходят под правила выше, но уже закреплены в коде. Не переименовываем без причины.

- `AgentChatEvent` и `AgentChatEnvelope` содержат `Chat`, хотя это события сессии: типы общие для
  сервера и клиента.
- В описании `AgentChatEnvelope` встречается «chat session». Читайте как `session`.
