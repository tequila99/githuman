# Глоссарий

Один термин — одно понятие. Используйте слово из колонки «Термин» в коде, комментариях, именах и
сообщениях интерфейса. Слова из колонки «Не писать» означают другое или двусмысленны.

Правило комментариев (ASD-STE100) — в [CLAUDE.md](../CLAUDE.md), раздел «Стиль кода». Новое понятие
сначала добавляется сюда, потом используется в коде.

## Git и изменения

| Термин | По-русски | Значение | Не писать |
|---|---|---|---|
| `repository` | репозиторий | Git-репозиторий, в котором запущено приложение. Сервер работает с одним. | `repo` в текстах (в коротких именах допустимо) |
| `worktree` | рабочее дерево | Файлы на диске. В коде — ref `WORKTREE`. | `working tree`, `disk copy` |
| `index` | индекс | Состояние git-индекса, то есть staged-содержимое. В коде — ref `INDEX`. | `staging area`, `cache` |
| `staged` / `unstaged` | в индексе / не в индексе | Изменения, добавленные в индекс, и остальные. Вкладки `Staged` и `Unstaged`. | `cached`, `indexed`, `pending` |
| `diff` | diff | Различия между двумя состояниями файла или всех файлов. | `patch`, `changeset` |
| `diff file` | файл в diff | Один изменённый файл в diff (тип `DiffFile`): путь, статус, hunks. | `changed file` для объекта данных |
| `hunk` | hunk | Непрерывный блок изменённых строк в diff-файле. | `chunk`, `block` |
| `card` | карточка | Раскрываемый блок одного diff-файла в панели diff (`DiffFileCard`). | `panel`, `item` |
| `full file` | весь файл | Режим карточки: показать файл с диска целиком, а не только hunks. | `full view` в текстах |

## Ревью и комментарии

| Термин | По-русски | Значение | Не писать |
|---|---|---|---|
| `review` | ревью | Сохранённый снимок diff с комментариями и статусом (`in_progress`, `approved`, `changes_requested`). | `session`, `PR` |
| `active review` | активное ревью | Ревью текущей ветки, в которое добавляются комментарии. | `current review`, `open review` |
| `snapshot` | снимок | Diff, замороженный при создании ревью (ADR 0003). Не путать с `worktree`: снимок не меняется. | `copy`, `backup` |
| `comment` | комментарий | Заметка ревьюера к строке, диапазону строк или файлу ревью. | `note`, `remark` |
| `thread` | ветка комментариев | Комментарии к одному месту в diff, показанные вместе. Только для комментариев ревью. | `thread` в других смыслах (например, «передать по цепочке») |
| `resolved` | решён | Признак комментария: вопрос закрыт. Непроверенные комментарии — `unresolved`. | `closed`, `done` |
| `suggestion` | предложение правки | Текст замены, приложенный к комментарию. | `fix`, `patch` |

## Агенты и чаты

| Термин | По-русски | Значение | Не писать |
|---|---|---|---|
| `agent` | агент | Внешняя программа, которая говорит по ACP (Claude Code, Cursor, Codex, pi). В интерфейсе — «Agent». | `harness`, `bot`, `assistant` |
| `preset` | пресет | Запись в конфиге о том, как запустить агента: команда, аргументы, пакет-адаптер (`AgentPreset`). | `agent config` |
| `adapter` | адаптер | Программа-мост между ACP и агентом, если у агента нет собственного ACP (например `claude-agent-acp`). | `wrapper`, `shim` |
| `session` | сессия | Серверный объект: процесс агента и его ACP-сессия (`AgentSession`, `/api/agent/sessions`). | `chat` для серверной части |
| `chat` | чат | То, что видит пользователь: вкладка и лента одной сессии. Каждая сессия — ровно один чат. | `conversation`, `dialog` |
| `transcript` | лента | Список записей чата: ваши сообщения, ответы, вызовы инструментов. | `history`, `log` (лог — другое) |
| `prompt` | запрос | Один ход пользователя: текст и контекст, отправленные агенту. | `query`, `request` для хода |
| `turn` | ход | Время от отправки запроса до ответа агента (`stop`). Статус сессии в ходе — `busy`. | `run`, `round` |
| `context` | контекст | Элементы, приложенные к запросу: `diff`, `file`, `review`, `attachment`. | `payload`, `input` |
| `resource URI` | URI ресурса | Идентификатор встроенного текста в запросе (`githuman://diff/…`, `…/review/…`, `…/attachment/…`). Не адрес, не разбирается. Подробности — [agent-context-uris.md](agent-context-uris.md). | `deeplink`, `link` |
| `mention` | упоминание | Путь файла репозитория, вставленный в поле ввода как `@путь`. Превращается в элемент контекста `file`. | `reference`, `tag` |
| `attachment` | вложение | Файл или изображение, загруженное с компьютера пользователя. Не из репозитория. | `upload` (как существительное) |
| `tool call` | вызов инструмента | Действие агента (чтение, правка, команда). В событиях — `tool`. | `action`, `step` |
| `permission request` | запрос разрешения | Вопрос агента перед действием; пользователь выбирает вариант. | `confirmation`, `approval request` |
| `auto-approve` | автоподтверждение | Флаг сессии: сервер сам отвечает «разрешить» на запросы разрешений. Выключен по умолчанию. | `yolo`, `bypass`, `trust mode` |
| `stream` | поток | Единый SSE-поток `/api/agent/events` со всеми чатами страницы. | `channel`, `socket` |
| `envelope` | конверт | Событие потока вместе с `sessionId` и сквозным `id` (`AgentStreamEnvelope`). | `message`, `packet` |
| `session state` | состояние сессии | Текущие `status`, `autoApprove`, `config` и открытые запросы разрешений чата (`AgentSessionState`). Сервер шлёт его в потоке перед повтором событий. Не путать с `snapshot` ревью. | `snapshot` (занят), `summary` |
| `panel` | панель | Правая панель агента. В коде — `AgentSidebar`. | `drawer` в текстах для пользователя |

## Безопасность

| Термин | По-русски | Значение | Не писать |
|---|---|---|---|
| `loopback` | loopback | Адрес `127.0.0.1`/`::1`/`localhost`. Агентские роуты работают только на нём. | `local host` |

## Известные исключения

Имена, которые не подходят под правила выше, но уже закреплены в коде. Не переименовываем без причины.

- `AgentChatEvent` и `AgentChatEnvelope` содержат `Chat`, хотя это события сессии: типы общие для
  сервера и клиента.
- В описании `AgentChatEnvelope` встречается «chat session». Читайте как `session`.
