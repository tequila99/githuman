# API ревью артефактов

Документ остаётся неизменяемым. Обсуждение, правки комментариев, скрытие и
решения сохраняются отдельными событиями. Git diff comments относятся к другому API.

## Треды и блокеры

`GET /api/artifacts/:id/threads` и MCP `reviews.list` возвращают `items`,
`nextCursor`, `storeId`, `storeEpoch`, `validationEpoch`, `artifactId` и
`blockerSummary`. `limit` (1–100) — максимум элементов, а не обещанный размер
страницы. Курсор списка привязан к store epoch и параметрам запроса.

В элементе списка есть `threadId`, `originArtifactId`, `inheritedFrom`,
`version`, `blocking`, `effectiveResolved`, `commentCount`, `anchor`,
`rootComment` и `lastComment`. Полных `comments` и `resolutions` здесь нет.
Текстовые превью и `anchor.quote` ограничены 1 KiB UTF-8; каждое превью содержит
`truncated`. Координаты anchor всегда относятся к оригинальному артефакту.

`blockerSummary.count` — полное число уникальных открытых блокеров;
`threadIds` содержит первые 100 ID, `truncated` указывает на остальные.
Полный набор доступен через страницы списка. `attention` означает, что
accepted-документ имеет открытые блокеры; статус accepted автоматически не меняется.
Отдельная сводка: `GET /api/artifacts/:id/review-state`, MCP `reviews.summary`.

Источники включают immutable lineage редакции и транзитивные replaces/supplements
каждого предка и каждой цели. Parent/references не переносят замечания.
Удалённый документ остаётся частью графа. Среди решений со scope в lineage
выбирается последнее по seq. Если такого решения нет, блокер наследуется от
открытых priority-путей; закрытия одного из нескольких путей недостаточно.
Смешанные циклы lineage/priority обрабатываются распространением открытого
состояния до устойчивого результата.

## Полные комментарии и история

`GET /api/artifact-threads/:id/comments` и MCP `reviews.comments` принимают
`afterIndex` (по умолчанию 0) и `limit`. `afterIndex` — число уже прочитанных
комментариев данного треда. Ответ: `storeId`, `threadId`, `version`, полный
`anchor`, `items`, `nextAfterIndex` (null в текущем конце).

Позиции не зависят от store epoch. Новые ответы дописываются, edit/hide не
меняют порядок. Каждая страница показывает текущее состояние, а не исторический
снимок всего обсуждения; её версия возвращается в `version`. Посторонняя запись
в хранилище не заставляет начинать чтение треда заново.

Текст скрытого комментария равен null и в списке, и в `comments`. Исходный текст
остаётся в `GET /api/artifact-threads/:id/history` / MCP `reviews.history`.
История принимает `afterSeq` и `limit`, возвращает `nextAfterSeq`. Тексты и события
истории не обрезаются; клиент продолжает чтение по возвращённому курсору.

Цитата нового anchor ограничена 64 KiB UTF-8. Длинный диапазон нужно уменьшить;
обычный комментарий без anchor остаётся доступен. Сервер сверяет исходный
hash, bodyStartLine, диапазон и точный quote, сохраняя CRLF и Unicode.

## Запись и права

- Создание: `POST /api/artifacts/:id/threads`, MCP `reviews.comment`.
- Ответ/правка/скрытие: `POST /api/artifact-threads/:id/events`,
  MCP `reviews.reply`, `reviews.edit`, `reviews.hide`.
- Прямое решение пользователя: `POST /api/artifact-threads/:id/decisions`.
  Scope и ожидаемая версия обязательны. MCP `reviews.resolve`, `reviews.reopen`,
  `reviews.set_blocking` требуют одноразового scoped grant; смысловой validation
  pass для этих действий не нужен. [Порядок подтверждения](artifact-lifecycle.md).

Агент может edit/hide только комментарии своей сессии. Новая сессия не получает
права на старые комментарии агента. Пользователь может редактировать комментарии
пользователей и скрывать любые; агентский текст редактировать нельзя.
Reply доступен независимо от автора треда. История хранит автора операции.
Повтор с тем же requestId возвращает прежний результат; actor и исходная команда
должны совпасть. Права не проверяются заново для уже записанного события,
но первоначальная проверка доступа к HTTP/MCP всё равно обязательна.

## Бюджет ответов

Общий мягкий бюджет сериализованных элементов страницы — 128 KiB, с учётом
JSON escaping. Если первый элемент крупнее, он возвращается целиком, чтобы
пагинация могла продвинуться. Anchor и envelope — дополнительный размер.
Лимиты текста/quote и тесты полного JSON-RPC envelope обеспечивают запас
до стандартного ReadBuffer MCP SDK. Это не гарантия числа токенов клиента.

Тот же helper используется для списков и истории артефактов и справочников.
Страница может стать короче limit; продолжать нужно по фактическому курсору,
а не вычислять смещение из запрошенного limit.
